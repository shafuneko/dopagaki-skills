## 2. 事実（測定）

### 2.1 測り方（数字より先に読む）

1. HTML を取得し、`<style>` の中身と `<link rel="stylesheet">` の CSS（最大12ファイル、1ファイル4MB未満）を取得して**連結**。
2. 連結したテキストに対して正規表現で**出現回数**を数える。
   - duration（明示）: `transition-duration:` / `animation-duration:` の値だけを ms 換算
   - duration（全体）: `transition:` / `animation:` **ショートハンドを含む**宣言内の時間トークン（`0.3s` `300ms`）を ms 換算
   - infinite: `animation-iteration-count: ... infinite` の宣言数と、`animation:` ショートハンド内の `infinite` を別々に
   - `!important`: 出現回数
3. 中央値は「昇順に並べた中央の値（偶数個なら下側）」。**0ms の宣言も除外していない**。
4. 重複を含む（メディアクエリごとの再宣言・ベンダープレフィックス違い・リセット CSS も数える）。**1回の取得**で、再取得の再現性は未検証。

## 3. 徴候

- **S-1**: 派手系とされる LP の duration 中央値は **300〜500ms** に集中する（9サイト中7サイト）。派手さの指標として「短い duration」を期待すると外れる。
- **S-2**: 中央値が同じでも**分布の裾が全く違う**。LIGHT THE WAY は中央値 400ms で最大 27.5秒、AHKAH は中央値 300ms で最大 3.4秒、サクマは 75〜500ms に閉じている。中央値1つでは区別できない。
- **S-3**: 常時ループ（infinite）は**ショートハンドに書かれる**。明示プロパティで infinite を持つのは眼鏡市場 5件のみ、ショートハンドでは LIGHT THE WAY 122件。仕様書的な書き方と実装の書き方が一致しない。
- **S-4**: duration 宣言の**総量**は 2〜866件と3桁の差がある。LIGHT THE WAY 866件・AHKAH 116件・サクマ 17件。「アニメの記述量」はサイト設計で全く違う。
- **S-5**: `!important` の多さは演出と連動しない。サクマは 563件で最多だが duration 17件・`@keyframes` 3件、LIGHT THE WAY は 32件で duration 866件。`!important` は「上書きの多さ」の指標で、派手さの指標ではない（**推定**）。
- **S-6**: `backdrop-filter` は9サイト中6サイトが 0件、`linear-gradient(` も3サイトが 0件。すりガラス・グラデは「派手なサイトの必須装備」ではない（少なくとも本サンプルでは）。

## 4. 印象（主観）

- 観察者1名（research-lp）。数値を見る前は「派手な LP は 100〜200ms の小気味よい応答で動く」と予想していた。実際は 300〜500ms が中心で、**予想より遅い側に寄っていた**。
- ただし 300ms という値は、NN/g の「単純なマイクロインタラクション 100–150ms、500ms 超は鈍い」という参照値（`docs/02-taxonomy.md` 付録）から見ると**中間〜遅め**。実際の画面を見ずに「速い/遅い」を語るのは危ういと感じた。これは印象であって測定ではない。

## 5. 仮説

- **「派手なLPは速い」は支持されない**（少なくとも duration 中央値では）。派手さは時間の短さではなく、**同時に動く量・ループの有無・外れ値の長さ**に出ている可能性がある。本サンプルでは中央値の分散が小さく（300〜500ms）、分散が大きいのは infinite 件数（0〜122）と宣言総量（2〜866）の方だった。
- **仮説（新規・番号未採番。lead が採番する）**: 派手さの強度は duration の中央値ではなく、①infinite の件数 ②duration 宣言の総量 ③分布の上側の長さ（秒単位の外れ値）の3つで近似できる。
- **H8（速度は平均ではなく局所のバーストで見る）と整合**: 中央値が同じ AHKAH（最大3.4秒）と LIGHT THE WAY（最大27.5秒）は、平均では区別できない。バーストの有無で分けるべき。
- 反証条件: 実ブラウザで `getAnimations()` を回収したとき、infinite の実行時件数と duration 中央値がサイト間で同程度に揃い、かつ体感の派手さの順位と一致しなければ、上記の仮説は棄却。

## 6. 反例・例外

- **CSS-in-JS の反例**: ナミナミダンボール沼は HTML 13KB・CSS 236B で、この方法では duration 2件しか取れない。実ブラウザでは激しく動いている可能性がある。**「数値が小さい＝静か」は言えない**（research §1.3）。
- **HTML が薄い反例**: サクマは HTML 2.6KB・`<img>` 1件。画像は JS 生成と**推定**され、実表示の枚数は不明。宣言 17件という数字も過小の可能性がある（未確認）。
- **`!important` の反例**: サクマの 563件は duration の少なさと同居する。`!important` が多い＝演出が多い、という読みは成り立たない。
- **測定不能の反例**: DAIKEN 80周年は URL 推測が外れて HTTP 404。**数値が無いことを「0」として表に入れていない**（欠測は欠測として扱う）。
- **見つからなかったもの**: 「派手なのに duration が 100ms 未満に集中する」サイトは、本サンプル9件では見つからなかった（n=9 の範囲で）。

## 7. 未翻訳・次に測る

- **未翻訳**: 「派手」の選定が主観で、母集団の定義がない。duration が 300〜500ms に集まる理由も、デザイン慣行なのか・ライブラリのデフォルト値なのか・CSS フレームワーク由来なのか、区別できていない。
- **次に測る**:
  1. 実ブラウザで `document.getAnimations()` を回収し、**実行時の** duration 中央値・infinite 件数を出す（本観察の最大の欠測）。
  2. CSS-in-JS サイト（ナミナミ等）を DevTools の Styles パネルから採取して再集計する。
  3. duration の分布（ヒストグラム）を取り、中央値ではなく**上位5%の外れ値**と**最頻値**を記録する。
  4. サンプルを増やす（n=9 は「傾向」を立てるには不足。`patterns/` に上げるのは観察3件以上が同じ徴候を指してから）。
  5. `prefers-reduced-motion` の記述数を集計し、`backlash` 軸の材料にする（今回は未計測）。
