# アクセシビリティと反発リスク — `backlash` 軸の一次情報

`docs/02-taxonomy.md` の `backlash` 軸と `evals/rubric.md` のゲート G を、一次情報で裏付けるための資料。
対象は**作品の知覚的特徴と実装**であり、人や診断の話ではない。医学的助言ではない（個別の症状は医療機関へ）。

- 最終更新: 2026-11-16

## 1. WCAG 2.2 の該当達成基準

| SC | レベル | 一言 |
|---|---|---|
| 2.2.2 一時停止・停止・非表示 | A | 5秒を超える自動の動きに停止手段 |
| 2.3.1 3回の閃光 | A | 1秒3回超の閃光を禁止 |
| 2.3.3 インタラクションからのアニメーション | AAA | 操作起点の動きを無効化できる |
| 1.4.2 音声の制御 | A | 3秒超の自動音声に停止・音量手段 |
| 1.4.3 コントラスト（最低限） | AA | 本文 4.5:1、大きな文字 3:1 |
| 1.4.11 非テキストのコントラスト | AA | UI部品・図形 3:1 |
| 2.4.7 フォーカスの可視化 | AA | キーボード位置が見える |
| 3.2.5 要求による変化 | AAA | 文脈の変化はユーザー要求時だけ |

### 2.2.2 一時停止・停止・非表示（A）

- **要件**: 自動で始まり、5秒を超えて続く「移動・点滅・スクロール」、および自動更新される情報に、一時停止／停止／非表示の手段（自動更新は更新頻度の制御でも可）。動きが必須の場合は例外。
- **壊しがち**: 無限マーキー、自動カルーセル、ライブカウンタ。`prefers-reduced-motion` を書いたから満たした、と誤認する（別物）。
- **チェック**: 5秒超の自動運動を列挙 → 各々にキーボードで到達でき、名前のある停止UIがあるか。再開位置が保持されるか。
- **出典**: [W3C Understanding 2.2.2](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html)

### 2.3.1 3回の閃光（A）

- **要件**: 1秒間に3回を超える閃光を置かない。超える場合は「一般閃光・赤閃光の閾値」未満に収める（詳細は §3）。
- **壊しがち**: グリッチ表現の高速反転、ストロボ的なトランジション、赤と白の交互点滅。「小面積なら安全」という誤用（面積条件は 10度視野あたり）。
- **チェック**: 全画面表示で録画 → フレームごとの相対輝度を算出 → 1秒窓で山と谷の組を数える。疑わしければ [PEAT](https://trace.umd.edu/peat/) 等のツールで判定。
- **出典**: [W3C Understanding 2.3.1](https://www.w3.org/WAI/WCAG22/Understanding/three-flashes-or-below-threshold.html)

### 2.3.3 インタラクションからのアニメーション（AAA）

- **要件**: 操作によって引き起こされる動きは、機能や伝える情報に必須でない限り無効化できる。
- **壊しがち**: ホバーで大きく動くカード、クリックで画面全体がスライド、スクロール連動の視差。「AAA だから任意」と扱い、実装しない。
- **チェック**: `prefers-reduced-motion: reduce` で再表示し、意味が伝わるか（rubric G4 の手順）。OS 設定を変えずに済む作品内トグルがあるとなおよい。
- **出典**: [W3C Understanding 2.3.3](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)

### 1.4.2 音声の制御（A）

- **要件**: 3秒を超えて自動再生される音声には、一時停止／停止、またはシステム音量と独立した音量制御を用意する。
- **壊しがち**: BGM の自動再生、ホバー効果音の連打、ミュート解除ボタンはあるが初期状態が大音量。
- **チェック**: 初期状態で無音か。音を出す前にユーザー操作があるか。独立した音量スライダーかミュートがあるか。
- **出典**: [W3C Understanding 1.4.2](https://www.w3.org/WAI/WCAG22/Understanding/audio-control.html)

### 1.4.3 コントラスト（最低限）（AA）／1.4.11 非テキスト（AA）

- **要件**: 本文 4.5:1 以上、18pt（24px）相当または 14pt 太字（18.66px）相当の大きな文字は 3:1 以上。UI部品の境界・状態、意味を持つ図形は背景に対し 3:1 以上。
- **壊しがち**: 動く背景の上に白文字、グラデーション上の細字、ネオン色の枠線。装飾と本文の区別が曖昧なまま全体を低コントラストにする。
- **チェック**: 動きを止めた状態と動いている状態の両方で、文字の下の最悪色と文字色を測る。フォーカスリングも 1.4.11 の対象。
- **出典**: [1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) / [1.4.11](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)

### 2.4.7 フォーカスの可視化（AA）

- **要件**: キーボード操作可能なUIは、フォーカスがあることが視覚的に分かる。
- **壊しがち**: `outline: none` の一括リセット、派手なアニメーションの中に埋もれるフォーカス、スクロールで追従しないフォーカス。
- **チェック**: Tab だけで主要導線を一周。フォーカスが画面外に出ないか、色だけでなく形でも分かるか。
- **出典**: [W3C Understanding 2.4.7](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html)

### 3.2.5 要求による変化（AAA）

- **要件**: 文脈の変化（画面遷移、フォーカス移動、新しいウィンドウ等）はユーザーの要求によってのみ起こす、またはそのような変化を切る手段がある。
- **壊しがち**: スクロール位置で勝手にページが切り替わる、一定時間で次の画面へ進む、入力途中でレイアウトが飛ぶ。
- **チェック**: 操作していないのに画面が変わる箇所を列挙。AAA なので合否ゲートではなく「減点・要検討」で扱う。
- **出典**: [W3C Understanding 3.2.5](https://www.w3.org/WAI/WCAG22/Understanding/change-on-request.html)

## 2. `prefers-reduced-motion` の正しい使い方

**原則**: 「全部止める」ではなく、**視差・移動・拡大・揺れを減らす／置き換える**。色や不透明度の変化、短いフェードは前庭刺激が小さく、残してよいことが多い。OS 設定は「動きを減らしたい」意思表示であり、フィードバックまで消す指示ではない。

```css
@media (prefers-reduced-motion: reduce) {
  .parallax { transform: none; }
  .card { transition: opacity 120ms linear; } /* 移動は消し、意味の変化は残す */
}
```

```js
const reduce = matchMedia('(prefers-reduced-motion: reduce)');
// CSS で止められないもの（動画・カルーセル・JS アニメ）は JS でも見る
if (reduce.matches) { cancelAnimationFrame(rafId); carousel.stop(); }
reduce.addEventListener('change', applyMotionPreference);
```

**対応しているのに効かない実装ミス**

1. CSS だけ対応し、`scroll` ハンドラ・`requestAnimationFrame`・Lottie/GSAP・`element.animate()` を止めていない。
2. `* { animation-duration: 0.01ms !important; }` の一括リセットで、`animationend` 待ちのUIやフェード完了後に出す要素が壊れる。
3. `transform` の視差・拡大を残したまま `opacity` だけ止めている（前庭刺激の主因が残る）。
4. `background-attachment: fixed`、スクロール連動、`IntersectionObserver` での移動を対象外にしている。
5. 自動再生動画・カルーセルは CSS では止められないのに、JS 側で `matchMedia` を見ていない。
6. 詳細度や読み込み順で上書きされ、実際には適用されていない（DevTools の Rendering → Emulate CSS media feature で確認）。
7. `reduce` を「完全静止」と解釈し、押した・進んだというフィードバックまで消して操作が分からなくなる。
8. `prefers-reduced-motion` を 2.2.2 の停止手段の代わりにしている（前者は環境設定、後者は作品内の制御）。

**出典**: [MDN prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)

## 3. 光過敏性てんかんの閾値（数値の出典つき）

W3C の定義（WCAG 2.2, 2.3.1）:

- **回数**: 1秒間に一般閃光 3回以下、かつ赤閃光 3回以下。
- **一般閃光**: 相対輝度の 10% 以上の対向変化があり、暗い側の相対輝度が 0.80 未満。
- **赤閃光**: 飽和した赤を含む対向遷移。WCAG 2.2 の作業定義では、一方の状態が `R/(R+G+B) ≥ 0.8` で、CIE 1976 UCS 色度図上の差が 0.2 超。
- **面積**: 同時に閃光している領域の合計が、10度視野あたり 0.006 ステラジアン以下（10度視野の 25% 以下）。1024×768 の画面では 341×256 px、CSS ピクセルでは 341×256 = 87,296 CSS px が目安。
- **映像の別基準**: ITU-R BT.1702 では「20 cd/m² 以上の輝度変化で、暗い側が 160 cd/m² 未満」。HDR で暗い側が 160 cd/m² 以上の場合は Michelson コントラスト 1/17 以上。
- **例外**: 0.1度未満の細かい均衡パターン（白ノイズ、細かいチェッカー）は閾値違反としない。

**運用**: 3回/秒を超えそうなら、まず「超えない」に落とす。面積で逃げるのは 10度視野の条件を理解している場合だけ。ループ GIF はループ全体で判定する。
**断定しないこと**: てんかんの発症リスクや個人差の推定。閾値は「多くの人を守るための工学的基準」であり、医学的診断基準ではない。

**出典**: [W3C Understanding 2.3.1](https://www.w3.org/WAI/WCAG22/Understanding/three-flashes-or-below-threshold.html)（0.006 sr・341×256・ITU-R BT.1702・赤の定義）

## 4. 前庭障害と motion sickness

- **有病率（確認できたもの）**: 米国 40歳以上で前庭機能障害の所見がある人は **35.4%**（NHANES 2001–2004、平衡機能検査による）。子どもでは **約5%** が過去1年にめまい・バランスの問題を経験（NIDCD）。
- **視覚誘導性の要因**: 視野全体の移動（全画面の流れる背景）、視差（層ごとに速度が違う）、揺れ・回転、大きなオブジェクトの拡大縮小、カメラの手ぶれ。MDN は「大きなオブジェクトの拡大やパン」を前庭刺激の例として挙げる。
- **メカニズム**: 視覚入力と前庭感覚の不一致が motion sickness を生む、という説明が用いられる。ただし**視覚誘導性 motion sickness の有病率は一次情報を確認できず（未確認）**。数値を書かない。
- **設計への示唆**: 画面全体を動かす表現は、部分的な動きより反発が大きい。`backlash` の記録では「動いた面積」と「視野に対する割合」を併記する。

**出典**: [Vestibular dysfunction prevalence (PMC4069154)](https://pmc.ncbi.nlm.nih.gov/articles/PMC4069154) / [NIDCD Quick Statistics](https://www.nidcd.nih.gov/health/statistics/quick-statistics-hearing) / [MDN prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)

## 5. 自動再生ポリシー（音付き）

| ブラウザ | ミュート自動再生 | 音付き自動再生の条件 |
|---|---|---|
| Chrome | 常に可 | ドメインへの操作履歴、MEI 閾値（7秒超の視聴・音声あり・前面タブ・200×140 px 超など）、ホーム画面追加／PWA インストール、iframe への権限委任 |
| Safari | 音声トラックなし／`muted` なら可 | 既定で音付きはブロック。ユーザー操作またはサイトごとの許可設定が必要。音声トラックが検出されると停止する |
| Firefox | 可 | 既定で音付きをブロックし、ユーザー操作があるまで保留（設定で変更可）。ユーザーが「許可」したサイトでは再生 |

- **共通**: 再生される前提でUIを作らない。`play()` の Promise を必ず `catch` し、拒否時に再生ボタンを出す。ミュートでも「動く映像」は 2.2.2 の停止対象。
- **出典**: [Chrome autoplay policy](https://developer.chrome.com/blog/autoplay) / [WebKit: Auto-Play Policy Changes for macOS](https://webkit.org/blog/7734/auto-play-policy-changes-for-macos/) / [WebKit: New Video Policies for iOS](https://webkit.org/blog/6784/new-video-policies-for-ios/) / [Mozilla Wiki: block-autoplay](https://wiki.mozilla.org/Media/block-autoplay)

## 6. ダークパターンと規制（断定しない）

- **EU DSA 第25条**: オンラインプラットフォームは、利用者を欺き、操作し、または自由で情報に基づく意思決定を実質的に歪める／妨げるようにインターフェースを設計・組織・運用してはならない。条文に「dark patterns」の語はないが、前文67が同種の慣行を想定する。
- **米 FTC**: 2022年9月のスタッフ報告書 *Bringing Dark Patterns to Light*。取消困難な定期購読、小さな文字に隠した条件等を例示。違法かどうかは個別判断。
- **日本**: 景品表示法5条（不当表示）は、2023年10月1日からステルスマーケティングを規制対象に追加。特商法は通信販売の広告表示（12条）や業務停止命令（15条）で対応。消費者庁の「デジタル取引・特定商取引法等検討会」は2026年9月10日に中間取りまとめを公表し、ダークパターン規律の方向性を示した段階で、**確定した新法ではない**。
- **書き方**: 個別のUIが「違法」と断定しない。「〜に該当しうる」「規制の議論がある」と書き、根拠条文・告示・報告書を示す。
- **出典**: [DSA 第25条（EUR-Lex）](https://eur-lex.europa.eu/eli/reg/2022/2065/oj) / [FTC 報告書 PDF](https://www.ftc.gov/system/files/ftc_gov/pdf/P214800+Dark+Patterns+Report+9.14.2022+-+FINAL.pdf) / [消費者庁 検討会（中間取りまとめ）](https://www.caa.go.jp/policies/policy/consumer_transaction/meeting_materials/review_meeting_005)

## 7. 子ども・青少年

- **WHO（5歳未満）**: 1歳未満は画面なし、1歳は座って画面を見る時間を推奨しない、2歳は1時間以内、3〜4歳は1時間以内（少ないほどよい）。睡眠は3〜4歳で10〜13時間（昼寝含む）。
- **WHO（5〜17歳）**: 余暇の画面時間を「制限する」よう勧告。**時間の数値目標は示していない**。
- **短尺動画の連続視聴に特化した公的勧告は確認できず（未確認）**。睡眠・注意への影響を断定せず、「長時間・夜間の視聴を避ける」等の一般的な注意にとどめる。
- **出典**: [WHO 5歳未満ガイドライン](https://www.who.int/publications/i/item/9789241550536) / [WHO 5〜17歳（2020）](https://www.who.int/publications/i/item/9789240015128)

## 8. 実装チェックリスト（上から潰す）

制作時にこの順で確認する。上ほど「取り返しがつかない（公開後に事故になる）」。

- [ ] 1. 閃光: 全画面で録画し、1秒3回超の輝度反転がない。赤の点滅がない（2.3.1）。
- [ ] 2. 音: 初期状態は無音。3秒超の自動音声には停止または独立音量がある（1.4.2）。
- [ ] 3. 停止: 5秒超の移動・点滅・自動更新すべてに、キーボードで使える停止／一時停止／非表示がある（2.2.2）。
- [ ] 4. 自動再生: `play()` の失敗を処理し、失敗時に再生ボタンを出す。ミュートでも動く映像は 3 の対象。
- [ ] 5. 動きの軽減: `prefers-reduced-motion: reduce` で視差・移動・拡大が止まり、意味は伝わる（2.3.3）。
- [ ] 6. JS 側: スクロール連動・rAF・外部アニメライブラリも同じ設定を見ている。
- [ ] 7. コントラスト: 本文 4.5:1、大文字 3:1、UI部品・図形 3:1。動きの中の文字も測る（1.4.3 / 1.4.11）。
- [ ] 8. フォーカス: Tab で一周でき、位置が見える。`outline: none` の一括リセットがない（2.4.7）。
- [ ] 9. 勝手な変化: 操作なしに画面が切り替わらない（3.2.5、AAA なので努力目標）。
- [ ] 10. ダークパターン: 取消・解約・閉じるが、隠されず・同じ視覚的重みで・1操作でできる。
- [ ] 11. 子ども向け: 画面時間・睡眠・夜間利用の注意書きを入れる（数値の断定を避ける）。
- [ ] 12. 記録: 測定値と測り方を `evals/rubric.md` の記録テンプレートに残す。
