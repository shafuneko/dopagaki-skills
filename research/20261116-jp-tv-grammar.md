# 日本のテレビ番組のテロップ・効果音の文法（Web 移植のための整理）

- 日付: 2026-11-16
- 種別: 調査メモ（確定方針ではない。[ADR 0005](../docs/04-decisions/) の切り分けに従い、ここは「調べたこと」の置き場）
- 目的: バラエティ・ワイドショー・通販番組の**テロップと SE の文法**を、Web / 動画制作に移植できる形で整理する
- 既存ファイルは変更していない（新規1ファイルのみ）

## 0. 出典の質の表記ルール

この文書では、各記述に次のラベルを付ける。数値は「誰が・何を対象に・どう測ったか」が分かるものだけを実務値として扱う。

| ラベル | 意味 | 例 |
| --- | --- | --- |
| 【一次】 | 放送局・制作会社・標準化団体が自ら公開した資料 | フジテレビ美術、東京美術、W3C |
| 【二次】 | 制作会社・実務者のコラム、まとめ記事 | video-knowledge.com、omniweb、note |
| 【体験談】 | 個人の経験則。サンプル数・測り方が不明 | 放送作家の回顧記事 |
| 【推測】 | この文書の書き手（エージェント）の推論。根拠は本文に添える | 「〜と考えられる」 |
| 【未確認】 | 探したが一次・二次とも見つからなかった | カット数の業界統計 |

テレビの制作現場の数値は、放送局が内部標準として持っていて外部公開されないことが多い。**見つからないものを「一般に〜秒」と書かない**のがこの文書の原則で、代わりに「測り方」を残す（第7節）。

## 1. テロップの種類と用途

### 1.1 放送局が公開している分類（アナログ期の整理）

フジテレビ美術の連載「はい！美術タイトルです vol.1」は、テロップを**合成方法**で4つに分けている。【一次】
出典: https://www.fujitv.co.jp/bijutsu/graphic/column/vol1.html

| 種類 | 仕組み | 主な用途 |
| --- | --- | --- |
| スーパーテロップ | 映像の上に白文字だけを合成 | 人物名・場所名など最短の情報 |
| ライブテロップ | 背景（帯・パネル）ごと合成 | 背景色で視認性を確保したいとき |
| ロールテロップ | 縦・横にスクロール | スタッフロール、お知らせ、長い文章 |
| 写植テロップ | 写植（文字組版）を撮影して合成 | 手書き・写植時代の高精細な文字 |

同じ記事の実務値【一次】:

- 情報番組では **6mm 程度の文字を画面下に2行**（アナログ放送の画面に対する実寸。現在の px 換算はできない）
- テロップカードは **125mm × 100mm**
- フリップは **356mm × 270mm**（普通フリップ）、**540mm × 387mm**（倍フリップ）、B4 厚紙
- 手書き時代は1回の放送で数十枚、多い時100枚超。コンピューター化後は**500枚以上**のテロップを出す情報番組も珍しくない
- 動きは「起こし」「回転」「引き抜き」。引き抜きはランキング・クイズ解答の発表に向き、十数段のものもある。後に「めくり」へ発展

→ **用途の原理**: テロップは「読ませる」より「一瞬で掴ませる」道具。だから文字サイズより**背景（帯）と動き**で認知を補助する。ロールだけが例外で、これは文章を読ませる用途。

### 1.2 制作会社が書いている現在の分類

東京美術（テレビ朝日系列に常駐するテロップ制作会社）の公開ページ【一次】:
https://www.tokyo-bijutsu.co.jp/visual.html

- テロップは**数秒間で目まぐるしく移り変わる**前提で設計されている
- フォント・サイズ・色・動きの4変数で表現力を上げる
- 言葉と言葉の間に「呼吸」のスペースを置く（詰め込みすぎない）
- フリップは手持ち小型から畳サイズのパネル、等身大パネル、プラカードまで
- **畳サイズの「めくり」パネル**が各局ワイドショーのトレンドで「視聴率のカギ」。二重・三重にめくるものもある
- 校正（誤字脱字）と校閲（事実関係・表現の矛盾）を分けて実施

→ ワイドショーの「めくり」は、テロップではなく**物理パネルを映す**演出。画面分割やカウントダウンと同じ「テレビ的な派手さ」の源だが、Web に移植すると情報量で負ける（6節）。

### 1.3 実務者が使う機能名と用途

映像制作20年の実務者ブログの用語辞典【二次】:
https://video-knowledge.com/telop-meaning-and-calling/

| 呼称 | 用途 |
| --- | --- |
| コメントフォロー（しゃべりテロップ） | 発話をそのまま文字にする。聞き逃しの補助と「笑いどころ」の指示 |
| サイドスーパー | 画面の四隅に継続表示。途中から見た視聴者に番組名・コーナー名・場所を示す |
| ツッコミテロップ | 出演者の発言に、演出側が代わりにツッコむ。バラエティで多用 |
| テロップベース（座布団） | 文字の下に敷く帯。視認性の向上と装飾。画面下1/3は lower third と呼ばれる |
| セーフティゾーン | ブラウン管時代に外周10%程度が隠れた領域。現在も UI を置かない余白として残る |

→ **フリップ・吹き出し・矢印・囲み**は、この表の「テロップベース」と「ツッコミテロップ」の派生と整理できる。用途は次のように対応する（この対応づけは【推測】。個別の出典があるわけではない）:

- **見出しテロップ**: コーナー名・結論を大きく1行。視線を止める
- **フリップ**: 文字だけでは伝わらない図・グラフ・イラスト・ランキング。テロップに収まらない情報の受け皿【一次: フジテレビ】
- **吹き出し**: 発言の帰属（誰が言ったか）を明示。ツッコミテロップと組み合わせる
- **強調（赤文字・縁取り・袋文字・ドロップシャドウ）**: 情報の階層づけ。「今見るべき1語」を色で分離する
- **オノマトペ**: 音・動き・感情の即時伝達。日本語の擬音語は種類が多く、1語で状況を説明できる
- **矢印・囲み**: 画面内の注目点を指定する。通販では「ここが違う」の指示に使う

### 1.4 文字組みの「呼吸」

東京美術の「呼吸」は、Web の字間・行間・余白に対応する。【一次】の記述を Web に読み替えると:

- 1行に詰め込まない（テロップは1行16文字程度が上限、2.1節）
- 文字と背景の間に余白（パディング）を取る
- 同時に複数の情報を出さない

## 2. 文字の見せ方の定番値

ここが一番「作り話」が混ざりやすい領域。**見つかった値と、見つからなかった値を分けて書く。**

### 2.1 見つかった値（出典つき）

video-knowledge.com の「テロップの文字サイズ・表示時間」記事【二次 / 実務者コラム】:
https://video-knowledge.com/character_size_time_timing/ （2025-03-13 更新）

| 項目 | 値 | 前提・注記 |
| --- | --- | --- |
| 表示時間の目安 | **4文字：1秒** | 洋画字幕のように位置とタイミングが一定の映像での値 |
| 動画テロップの表示時間 | **4文字：1秒 + α** | コメントフォロー・煽り・説明はやや長めに |
| 1行の文字数 | **16文字程度、2行以内** | 1画面 **30〜35文字**程度まで |
| 説明テロップ | 語句1行 + 説明文2行 | 3行構成も可 |
| 読み速度の補正 | 編集者は視聴者の **1.5〜2倍** 速く読む前提 | 表示を1.5倍長く取る |
| 出すタイミング（コメントフォロー） | 音より **1〜4F 先行** | 30fps なら 33〜133ms 先行 |
| 出すタイミング（カット替わり） | 板付き（カット頭から表示） | カットの頭に文字が乗っている状態 |
| 消すタイミング | 話し終わりから **1拍遅れ** | 早く消すと「読み切れない」 |
| 説明テロップの位置 | 話題を振った**後**（A:話題前=NG、B:同時、C:話題後=推奨） | 先に文字を出すとネタバレになる |

同記事は根拠として**視覚 170ms / 聴覚 130ms** の論文（映像学誌）を引いている。これは「音より映像が遅れて知覚される」ことの説明で、テロップを音より先行させる理由づけに使われている。

同じ内容が BlueFlame（動画制作会社）の Wantedly 記事にもある【二次】:
https://www.wantedly.com/companies/blueflame/post_articles/900170 （2024-04-24）
ただし文面がほぼ同一で**転載の可能性が高い**ため、独立した2つ目の証拠としては数えない。

**字幕放送の文字数**（アクセシビリティ側の事実。テロップとは目的が違うが、比較対象として有用）【二次: Wikipedia 経由】:
https://ja.wikipedia.org/wiki/文字多重放送

| 局 | 1行の文字数 | 時期 |
| --- | --- | --- |
| 基本 | 15.5文字 | — |
| NHK | 18.5〜19.0文字 | 2018-10 以降 |
| テレビ朝日 | 一部 2023-09 → 全番組 2024-04 | — |
| TBS / CBC | 21.0文字 | 2025-04 から |

キー局は2行基本（NHK・日本テレビは3行も）。出典が Wikipedia なのは、総務省の指針 PDF 本文の文字数規定を確認できなかったため（第7節）。

→ **読み取れること**: 字幕の 15.5〜21文字/行 と、テロップの 16文字/行 はほぼ一致する。**「1行16文字」は日本語の可読性から来る値**で、テレビ固有の秘密ではない。【推測】

### 2.2 見つからなかった値（未確認）

以下は探したが見つからなかった。**「定番は3px」のような数字を書かない。**

- 縁取り（袋文字）の標準的な太さ（px / mm）。画面サイズ・解像度・書体で変わるため、統一値があるとは考えにくい
- 1画面あたりの色数の上限（「3色まで」等）。制作会社のガイドラインは非公開
- フォントの指定（ゴシック体・極太が定番という記述は複数あるが、**具体的な書体名とウェイトの一次資料は未確認**）
- 同時表示できるテロップの枚数（画面分割の上限）

### 2.3 代わりに使える「測り方」

数値が無い領域は、自分の素材で測って持つほうが早い。手順は第7節にまとめた。

## 3. 効果音（SE）の文法

### 3.1 音源の利用実態

**効果音ラボ** https://soundeffect-lab.info/ 【一次: 配布元の利用条件】

- フリー素材。**商用利用無料、クレジット表記・リンク不要**
- 禁止: アダルト利用、素材の再配布
- サイト自身が「業務用効果音の品質」「音響のプロの現場でも使われています」と書いている
- ポン出し用の Web アプリを提供（ブラウザで音を鳴らす前提の設計）

**VSQ plus+** https://vsq.co.jp/plus/ja 【一次: 配布元】

- 商用利用可の無料音源 **1,726本**
- 「テレビ映像制作のプロが制作」、クレジット不要

→ テレビ的な SE は、**有料の音源ライブラリを買わなくても同じものが手に入る**状態になっている。ただし「テレビで使われている音源がこれ」という統計は無い（第7節）。

### 3.2 用途別のラインナップ（実際の商品名から逆算する）

効果音ラボの「演出・アニメ」カテゴリの実際の収録内容【一次: 配布元のカタログ】:
https://soundeffect-lab.info/sound/anime/

| 機能 | 収録されている音（商品名） | 使われ方 |
| --- | --- | --- |
| 画面転換 | 「シーン切り替え1（木琴）」「シーン切り替え2（ブオッ）」 | カットの頭に1発。木琴＝軽い場面転換、ブオッ＝強制送還・場面急変 |
| タイトル表示 | 「タイトル表示」「ニュースタイトル表示1〜4」「タイプライターで文字を打つ1/2」 | 文字が出る瞬間に同期。タイプライターは1文字ずつ |
| スタンプ・登場 | 「ジャン！何かを紹介する時などに」「ジャジャーン紹介・登場」「ペタッ スタンプをつく時などに」「パッ 可愛くメッセージ表示」 | テロップが「置かれる」動作に音を付ける |
| 正解 | クイズ正解1〜5（ピンポン / 鉄琴 / ハープ / シンセ / 高め） | 正解の瞬間。ピンポンが最も記号化している |
| 不正解 | クイズ不正解1「ブブー」/ 2「残念でした」 | 不正解の瞬間。ブブーは即座に意味が伝わる |
| 出題 | クイズ出題1「デデン」/ 2 | 問題が切り替わる瞬間 |
| 制限時間 | 制限時間タイマー、その倍速版 | カウントダウン中の残り時間。倍速版は「焦り」の演出 |
| 早押し | 早押しボタン1/2 | 押した瞬間の触感 |
| ツッコミ | 「ビシッとツッコミ1（漫才演出）」「2（動画のツッコミ演出）」「3（ハリセンでどつく）」 | ツッコミテロップとセット |
| 間・ズッコケ | 間抜け1〜7、ショック1〜6、チーン1/2、ボヨヨーン、ずっこけるドテーン、寒いギャグで突風 | 「気まずい沈黙」「失敗」「寒い」の記号化 |
| カウントダウン | 「カウントダウン電子音 プッ、プッ、プッ、ピー」 | 通販・クイズの締め切り演出 |
| 笑い・歓声 | 男衆「オウ！」「イエーイ！」、大勢で拍手、スタジアム歓声 | スタジオの空気を後付けする |

→ **文法として読めること**（【推測】を含む）:

- SE は**意味の記号**として使われている。「ピンポン＝正解」「ブブー＝不正解」は、音を聞いた瞬間に状況が分かる。映像を見ていなくても理解できる
- 1つの動作に1つの音。**重ねない**（「ジャン」＋「ペタッ」を同時に鳴らすと、どちらの動作か分からなくなる）
- 音の長さは**0.5〜2秒程度**に収まるものが中心（商品名から見た傾向。実測ではない）
- 余韻（残響）より**アタック（立ち上がり）**が大事。頭が揃わないとテロップと同期しない

### 3.3 長さ・間隔の数値（未確認）

- SE の標準的な長さ（秒）、SE と SE の間隔、1分あたりの本数 → **一次・二次とも見つからず**
- 測り方は第7節

## 4. テンポ（カット数・尺とテロップ枚数）

### 4.1 見つかった数値

**映画のショット解析**（日本認知科学会 2018 大会発表 PDF）【一次に近い: 学術発表】
https://www.jcss.gr.jp/meetings/jcss2018/proceedings/pdf/JCSS2018_sP1-11.pdf

- 対象: 邦画20作品
- 平均上映時間 **115.34分**（SD 16.12）
- 1作品あたり平均ショット数 **704.75**
- → 平均ショット長 **約9.8秒**

これは**映画**の値で、テレビバラエティの値ではない。バラエティはこれより速いという印象はあるが、**その印象を数値で裏づける資料は見つからなかった**。

**BPM 基準のカット間隔**（制作会社のコラム）【二次】
https://omniweb.jp/m124

| BPM | 推奨カット間隔 | 最短カット間隔 |
| --- | --- | --- |
| 90 | 1.3〜2.7秒 | 0.67秒 |
| 100 | 1.2〜2.4秒 | 0.6秒 |
| 110 | 1.1〜2.2秒 | 0.55秒 |

これは「BGM に同期させる」ための一般論で、テレビ番組の実測値ではない。ただし **0.6秒 = 1分100カット** に相当するので、「1分あたりのカット数」を考えるときの上限の目安にはなる（計算は自明: 60 ÷ 0.6 = 100）。

### 4.2 未確認

- テレビバラエティの「1分あたりカット数」の業界標準。**統計が見つからない**
- VTR の尺とテロップ枚数の関係（フジテレビ記事の「500枚以上」は枚数のみで、尺が書かれていない）
- ジャンル別（バラエティ / ワイドショー / 通販）のカット数の差

### 4.3 尺とテロップ枚数の概算（【推測】）

フジテレビ記事の「500枚以上」を、仮に30分の情報番組とすると **約17枚/分**、1時間なら **約8枚/分**。ただし尺が不明なので**この計算は根拠にならない**。自分で測るときの比較対象として置いておく。

## 5. 通販番組・ワイドショーの煽り

### 5.1 定型句（放送作家の回顧）【体験談】

note「通販番組でよく出てくる言葉ベスト10」（放送作家歴30年と自称）:
https://note.com/clever_crow6318/n/n1d09559964bc

1. **恐怖を煽る**: 「このまま放っておくと危険です」
2. **驚きリアクション**: 「え〜本当？信じられない！」← 効果を断言できないときの代替演出
3. **比較で安さ**: 「同じ品質なら通常2万円以上」「1日コーヒー1杯分」
4. **限定感**: 「今だけ、ここだけ」
5. **権威**: 白衣の出演者
6. **共感**: 視聴者の代弁
7. **季節感**: 今の時期に必要
8. **人生100年**: 長寿への訴求
9. **特典強調**: 今申し込むと付く
10. **実証・決めフレーズ**

同記事は、薬機法・景品表示法を避けるために**効果効能を「匂わせる」記述**にしている、と書いている。有料部分以降は未取得。

→ この10項目は**文章の型**であって、テロップの型ではない。テロップに落とすと「赤文字で短く」「体言止め」「矢印で対象を指す」になる（【推測】）。

## 6. Web への移植（CSS）

### 6.1 袋文字（縁取り）

`-webkit-text-stroke` は **Safari / Chrome 系の独自拡張**で、標準の `text-stroke` は存在しない。MDN のリファレンス:
https://developer.mozilla.org/ja/docs/Web/CSS/Reference/Properties/-webkit-text-stroke

```css
.telop {
  font-family: "Noto Sans JP", "Hiragino Kaku Gothic ProN", sans-serif;
  font-weight: 900;            /* 極太。フォントに無いウェイトは合成されるので注意 */
  font-synthesis: none;        /* 合成太字を禁止（縁取りと干渉する） */
  color: #fff;
  -webkit-text-stroke: 6px #000;
  paint-order: stroke fill;    /* 縁を文字の背面に（対応ブラウザのみ） */
}
```

**注意点（重要）**:

- `-webkit-text-stroke` の線は**字面の中心線に引かれる**（外側だけに付かない）。太くすると文字が痩せる。上の 6px は「例」であって実測の標準値ではない
- `paint-order: stroke fill` で縁を背面に回せるが、**Chromium 系では `-webkit-text-stroke` と併用した `paint-order` が効かない**と MDN の互換注記にある（「full support」と報告されているが実際は未対応、という記述）。Firefox / Safari では `paint-order` + `text-stroke`（`-webkit-` 版含む）で動く。**この違いは実機で要検証**
- Chromium で縁を背面にしたい場合は、SVG の `<text>` に `paint-order="stroke fill"` を使うか、6.2 の多層 `text-shadow` に逃げる

```html
<!-- SVG なら paint-order が確実に効く -->
<svg viewBox="0 0 600 160" role="img" aria-label="今すぐ">
  <text x="300" y="120" text-anchor="middle"
        font-size="120" font-weight="900" fill="#fff"
        stroke="#000" stroke-width="12" paint-order="stroke fill">今すぐ</text>
</svg>
```

### 6.2 多層 text-shadow（縁取りの代替）

```css
.telop--shadow {
  color: #fff;
  text-shadow:
    2px 0 0 #000, -2px 0 0 #000, 0 2px 0 #000, 0 -2px 0 #000,
    2px 2px 0 #000, -2px 2px 0 #000, 2px -2px 0 #000, -2px -2px 0 #000,
    0 0 12px rgba(0, 0, 0, .6);
}
```

- 8方向 + ぼかしで「縁 + ドロップシャドウ」を1つの宣言で作れる。ブラウザ差が少ない
- 角（斜め）が弱いので、太い縁には向かない。**2〜3px 程度まで**が実用（【推測】。実測ではない）
- 文字が痩せないのが `-webkit-text-stroke` に対する利点

### 6.3 グラデーション文字（通販の「キラキラ」）

```css
.telop--grad {
  font-weight: 900;
  background: linear-gradient(180deg, #fff 0%, #ffe066 45%, #ff9f1a 55%, #fff 100%);
  -webkit-background-clip: text;
  background-clip: text;
  -webkit-text-fill-color: transparent;  /* color: transparent より Safari で安全 */
  color: transparent;
}
```

- `background-clip: text` は `-webkit-` 接頭辞がないと動かないブラウザがある
- **縁取りと併用すると縁が消える**ことがある（`text-fill-color: transparent` は縁の色も消すため）。縁を付けたいときは、親要素に `filter: drop-shadow()` を使うか、縁を別レイヤ（`::before` に同じ文字）で重ねる

### 6.4 やりすぎの線引き（WCAG との衝突）

WCAG 2.2 の G18（背景が一様でない場合のコントラスト確保）:
https://w3c.github.io/wcag/techniques/general/G18

- 文字の周囲に**幅1px以上の細い縁**を付けると、その縁は「文字の一部」として扱われる。**縁の色と背景のコントラスト**で 4.5:1 を満たせばよい
- 逆に、**内側を埋めるほど太い縁（ハロー）は「背景」とみなされる**。この場合、文字の色と**縁の色**のコントラストが 4.5:1 必要になる（Understanding 1.4.3 の注記）
- しきい値: 18pt（24px）未満、または太字で 14pt（約18.66px）未満は **4.5:1**。それ以上は **3:1**。1pt = 1.333px

→ **テレビ的な「極太の白フチ + 赤文字」は、縁が太いほど「背景」になり、赤と黒のコントラストが問われる**。赤（#ff0000）と黒のコントラストは約 5.25:1 なのでぎりぎり通るが、赤（#e60000）を暗くすると落ちる。**縁を太くするほど可読性が上がるわけではない**。

その他の線引き:

- 縁取りでコントラストを稼ぐのは G18 の範囲内。ただし**縁の外側の背景**が動画・写真だと、縁と背景のコントラストも必要（縁が白で背景が白だと消える）
- 点滅・フラッシュは WCAG 2.3.1（1秒に3回以上の閃光を避ける）。テレビ的な「バーン」という白フラッシュはこれに触れやすい
- 自動でループするカウントダウン・スクロールは WCAG 2.2.2（一時停止・停止・非表示の手段を用意する）。通販の「今すぐ」演出をそのまま Web に置くと抵触する
- `prefers-reduced-motion` で煽りアニメを止める

```css
@media (prefers-reduced-motion: reduce) {
  .telop--pulse { animation: none; }
}
```

### 6.5 「テレビらしさ」を残しつつ Web で成立させる原則（【推測】）

1. **1画面1メッセージ**。テレビは同時に複数のテロップを出すが、Web はスクロールで読むので、同時表示は1つに絞る
2. **縁取りは 2〜4px まで**。それ以上は字面を食う
3. **色は3色まで**（白・黒・アクセント1色）。テレビの多色使いは、画面が大きく視距離が遠い前提
4. **アニメは「出る」だけ**。「回転」「引き抜き」は Web では安っぽく見えやすい
5. **効果音はユーザー操作の後**に鳴らす。自動再生はブラウザにブロックされるうえ、WCAG 1.4.2（音声の制御）に触れる

### 7.2 測り方（自分でデータを取るときの手順）

**カット数**

1. 対象番組を3本以上、ジャンルを揃えて選ぶ（バラエティ / ワイドショー / 通販）
2. 各番組の冒頭5分と中盤5分を、CM を除いて書き出す
3. カット（ショット）の切れ目をフレーム単位で記録する。自動検出（PySceneDetect 等）を使うなら、閾値を固定して**同じ設定で全番組に適用**する
4. 「カット数 ÷ 分数」で1分あたりを出す。最小・中央値・最大を併記する
5. 併せて「テロップの枚数」も同じ区間で数える（テロップが消えて別のテロップが出たら1枚と数える）

**テロップの表示時間**

1. 対象区間を 30fps で書き出す
2. テロップが出たフレームと消えたフレームを記録する
3. 「文字数 ÷ 表示秒」で**秒/文字**を出す。4文字1秒なら 0.25秒/文字
4. 文字数は句読点・記号を除いて数える（数え方を固定しないと比較できない）

**SE の長さ・間隔**

1. 音声を波形で表示する（Audacity 等）
2. SE の立ち上がり（アタック）から減衰の終わりまでを秒で測る
3. 直前の SE との間隔、直後のテロップとのズレ（フレーム）を測る
4. 1分あたりの SE 本数を数える

**縁取りの太さ**

1. 画面を 1920×1080 でキャプチャする
2. 文字の高さ（px）と縁の太さ（px）を測り、**「縁の太さ ÷ 文字の高さ」の比**で表す。絶対値では比較できない
3. 縁の色・文字の色・背景の色を記録し、コントラスト比を計算する

## 8. まとめ（Web に持ち帰る3つ）

1. **テロップは「読ませる」より「掴ませる」**。1行16文字・2行以内・1画面1メッセージ。表示時間は「4文字1秒 + α」が出発点
2. **SE は意味の記号**。1動作1音、アタックを揃える。効果音ラボでテレビ的な記号はほぼ揃う
3. **縁取りは諸刃**。太い縁は WCAG 上「背景」になり、文字色と縁色のコントラストが問われる。Chromium では `paint-order` + `-webkit-text-stroke` が効かないので、SVG か多層 `text-shadow` で代替する
