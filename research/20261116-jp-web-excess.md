- 対象: 1994〜2026年の日本のWeb広告・Webサイト・ソーシャルゲーム・LP・イベント告知。

補足（表の行に対応）:

- 1994年の「最初のバナー」は複数社が名乗っており、本メモでは**一次アーカイブを取得できていない**。年号と媒体だけを採用し、デザインの過剰さは扱わない。
- Flashの「過剰さ」は、当時の実物ページを取得できていないため、**表現の具体（点滅周期・同時アニメ数）は未確認**。確認できたのは終了日だけである。
- 消費者庁の文書は表現の派手さを規制していない。規制対象は「異なる符票の組合せ」という**仕組み**であり、Q12は「景品表示法は、消費者の射幸心をあおる行為それ自体を規制するものではありません」と明記している。つまり**演出の過剰さは法規制の外**にあり、抑制はアクセシビリティ基準か自主規制に委ねられている。
- 2026年の脳汁横丁は、リリース本文に「光と音の脳汁空間」「光と音に包まれた脳汁祝祭空間」「提灯マッピングステージ」と、光と音を主題化する記述が繰り返される。物量も明示的で、オリジナルグッズ11種、くじ1回777円、商品総額2,558,910円（税込）と記載されている。

## 3. 実装上の特徴（測れる形）

以下は「印象」ではなく、**画面上で数えられる量**として定義したもの。左2列が定義、右2列が根拠と測定手順。

| 指標 | 定義（単位） | 参照できる基準値・出典 | 測り方（提案・未実施） |

読み取れること（**事実**）:

- 点滅・自動再生については、**規格側に具体的な数値の線引きがある**（3回/秒、87,296 CSS px、5秒）。つまり「過剰かどうか」はこの3つで機械的に判定できる。
- 一方、**情報密度・音の大きさ・煽りの重複度には公的な閾値が無い**。テロップ枚数やSEの尺は、制作会社・素材販売サイトの**経験値の記述（二次情報）**しか見つからなかった。
- ガチャ演出は、法規制が「仕組み」に向けられ、演出そのものには及んでいない（§2の消費者庁Q12）。

推測（**推測**と明記）:

- 日本のWeb表現の過剰さは、「TVの画面文法（テロップ＋SE＋フリップ）をそのままWebに持ち込んだ」経路と、「ガチャの当選演出をWebのマイクロインタラクションに流用した」経路の2つが重なって形成された、という仮説。本メモでは**どちらの経路も一次資料で裏づけられていない**。

### 3.1 閾値の換算例（計算であり、測定ではない）

- WCAG の「341×256 CSS px」を、当時の基準解像度1024×768に当てはめると `87,296 / 786,432 ≒ 11.1%`。つまり**画面の約1割が同時に点滅すると閾値級**、という読み方ができる（この除算は私の計算。仕様が「11.1%」と書いているわけではない）。
- 「10度視野の25%」という表現と「341×256」は同じものを指す。**面積比25%と画面比11.1%は別物**なので、混同すると判定が甘くなる。
- 5秒の根拠は仕様本文に「注意を引くには十分だが、待ち切れないほど長くはない」と書かれている（出典: 2.2.2 の Intent）。**生理学の数値ではなく、待てるかどうかの設計判断**である点は実装上も重要。

### 3.2 数値が無い領域をどう扱うか

- 情報密度（文字量・要素数）と音量は、**公的な閾値が見つからなかった**。したがって本リポジトリで規則化するなら、「数値で縛る」のではなく「測り方と記録形式を固定する」方が再現性が高い。
- 具体的には、`observations/` に1事例1ファイルで「媒体・画面サイズ・点滅Hz・点滅面積・自動開始からの秒数・停止UIの有無・テロップ枚数/分・SEの尺・限定文言の数」を同じ列で書く。列を固定すれば、後から傾向を数えられる。

## 4. 現代のフロントエンドに移植できる形

「過剰さ」を否定せず、**段階と停止手段つきで再実装する**ための最小構成。以下は実装案であり、動作検証はしていない（**未検証**）。

1. 点滅は `steps()` で離散化し、周期を**明示的な変数**にする。秒数ではなく Hz で持つと WCAG の3回/秒と直接比較できる。

```css
:root { --blink-hz: 2; }              /* 2回/秒 = 基準内 */
.blink {
  animation: blink calc(1s / var(--blink-hz)) steps(1, end) infinite;
  animation-iteration-count: 4;        /* 5秒以内に終わる */
}
@keyframes blink { 50% { opacity: .15; } }
@media (prefers-reduced-motion: reduce) {
  .blink { animation: none; opacity: 1; }
}
```

2. 自動再生・自動更新には**必ず停止トグル**を1つ置く（要素ごとに増やさない）。WCAG 2.2.2 の注記も「単一の mechanism が望ましい」としている。

```html
<button type="button" aria-pressed="false" id="motion-toggle">動きを止める</button>
<script>
  const btn = document.getElementById('motion-toggle');
  btn.addEventListener('click', () => {
    const on = btn.getAttribute('aria-pressed') === 'true';
    btn.setAttribute('aria-pressed', String(!on));
    document.documentElement.classList.toggle('no-motion', !on);
  });
</script>
```

3. 音は**ユーザー操作後にだけ**鳴らす（自動再生の音は WCAG 2.2.2 ではなく別基準の領域。本メモでは当該基準の本文を未確認）。演出の「当たり」は、音量ではなく**視覚の段階**で作る。

4. 「過剰さ」をトークン化して段階を持つ（L0=静止 / L1=1要素のみ点滅 / L2=点滅＋SE / L3=全画面フラッシュ）。L3 は既定で無効、`prefers-reduced-motion` と回線速度で降格する。**この段階設計は本メモの提案であり、出典は無い**。

5. 計測を自動化するなら、`requestAnimationFrame` で対象要素の computed style（opacity / transform）を毎フレーム記録し、変化回数を1秒窓で数える。色の輝度差は canvas の `getImageData` で取れる。**実装も検証もしていない**。

6. 演出の「尺」は固定値で持つ。テロップ型の情報提示なら、1枚あたりの表示時間を**読字数/秒**から逆算する（例: 20字を秒6字で読むなら約3.3秒）。この逆算は一般的な読速の仮定に依存し、**本メモでは根拠資料を確認していない**。

移植の判断表（**提案**。出典ではなく、§2〜§3の整理として書く）:

| 用途 | 許容する段階 | 理由 |
| --- | --- | --- |
| 広告バナー・FVの注意喚起 | L1（静止画＋1要素の緩い動き） | 点滅は3回/秒の線に触れやすい。面積を絞れば回避できる |
| ガチャ・抽選の結果表示 | L3を**ユーザー操作後1回だけ** | 操作起因なら「自動開始」に当たらない。尺は固定し、スキップ可にする |
| 期間限定・セール告知 | L2（動き＋音は操作後） | 煽り要素の重複は規制外だが、停止手段は必要 |
| 常時表示の背景アニメ | L0〜L1、かつ停止トグル必須 | 5秒を超える自動アニメは 2.2.2 の対象 |
| 読み物・記事本文 | L0 | 可読性が目的。演出は本文の外に置く |

この表の「L0〜L3」は §4-4 の段階定義に対応する。**境界の数値（どのくらいの面積まで L1 か）は決めていない**。決めるには §3 の測定を実例で回す必要がある。
