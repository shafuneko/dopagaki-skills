# 0003 構造は仮。chat.txt を共通の窓口にする

- 状態: 採用
- 日付: 2026-11-16

## 背景

2つの環境（2人＋各自のエージェント）が同じリポジトリを編集する。どちらの方針が正しいかを先に決めることはできないし、
片方が間違った構造にしても、もう片方が直せなければリポジトリは腐る。また、エージェント同士は非同期で動くため、
「今どちらが何をしているか」を知る手段が要る。

## 決定

1. **構造は仮**とする。フォルダ構成・軸・スキルの分割は自由に変えてよい。
2. 変更時は必ず4点セット: 索引の更新 / ADR 1枚 / `chat.txt` への引き継ぎ / 相手の未コミットを壊さないこと。
3. **`chat.txt` を両側共通の窓口**とする。追記のみ、`- YYYY-MM-DD HH:MM <名前>: 本文` 形式。
4. 意見が割れたら chat.txt で提案し、止まるなら「暫定」と明記して進める。

## 理由

- 正しさを先に固定すると、間違っていたときに直せない。**直せること**を優先する。
- エージェントは相手のコンテキストを持たない。共有ログがないと、同じ議論を繰り返すか、黙って上書きするかのどちらかになる。
- 追記専用ログは衝突に強く（`merge=union`）、人間にも読める。

## 帰結

- chat.txt は長くなる。決定事項は ADR へ移し、ログには経緯だけ残す。
- エージェントの慣習ファイル（`CLAUDE.md` 等）は `AGENTS.md` へのポインタのみ。規約の二重管理をしない。
