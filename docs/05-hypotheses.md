# 仮説台帳

規則を先に作らず、まず**検証可能な仮説**として置く。各仮説は観察が溜まった時点で支持/棄却を判定する。
棄却された仮説は消さず、`状態: 棄却` と理由を残す（同じ議論の蒸し返しを防ぐため）。

状態: `未検証` / `検証中` / `支持` / `棄却`

---

## H1 テンポ仮説

**主張**: 変化の間隔が短いほどドパガキ感は上がる。ただし閾値があり、ある間隔より短いと「速い」ではなく「壊れている」と知覚される。

- 予測: `tempo` 軸のスコアと主観評価が正相関する。ただし極端値で頭打ちまたは下降。
- 検証方法: 同一素材の再生速度を変えた比較、または変化間隔の異なる素材群の評定。
- 棄却条件: 間隔を短くしても評定が上がらない、または単調増加し続ける（閾値が無い）。
- 状態: 未検証

## H2 予測誤差仮説

**主張**: 予測を裏切る回数と幅が大きいほど強い刺激になる。規則的な変化は飽和する。

- 予測: `reward` 軸の「予測不能性」と主観の「飽きなさ」が相関。
- 検証方法: 規則的アニメと不規則アニメの比較。同一作品内の variation。
- 棄却条件: 不規則にしても評定が変わらない。
- 状態: 未検証

## H3 過剰性仮説

**主張**: 情報密度・装飾密度・色数が多いほどドパガキ感は上がる。

- 予測: `intensity` 軸の各指標と評定が正相関。
- 棄却条件: 密度を上げると「チープ」「読みにくい」が勝ち、評定が下がる（→ H5 と統合）。
- 状態: 未検証

## H4 即時性仮説

**主張**: 操作から報酬までの遅延が短いほど効く。100ms を超えると「鈍い」と感じ始める。

- 予測: 応答時間と「気持ちよさ」評定の負相関。100–150ms 付近に変曲点。
- 検証方法: 同一UIの遅延を段階的に変えた比較。
- 棄却条件: 遅延を変えても評定が変わらない。
- 状態: 未検証

## H5 反発U字仮説

**主張**: 刺激の強度を上げると、ある点までは快・没入が上がるが、超えると不快・チープ・酔いに転じる（U字）。

- 予測: 強度指標と評定の関係が逆U字。`backlash` 軸のスコアが急上昇する点がある。
- 検証方法: 強度を段階的に振った試作の評定。
- 棄却条件: 単調増加、または最初から下降。
- 状態: 未検証

## H6 対比仮説

**主張**: 静かな区間（余白・無音・静止）を挟むと、その後の刺激が強く知覚される。

- 予測: `restraint` 軸のスコアが高い素材でも、`tempo`/`intensity` のピークが高いと評定が高い。
- 棄却条件: 静区間の有無で評定が変わらない。
- 状態: 未検証

## H7 慣れ（飽和）仮説

**主張**: 同じ刺激の反復で評定は下がる。変化の**種類**が効くのは、慣れをリセットするため。

- 予測: 同一素材の長時間視聴で評定が低下し、変化の種類が多い素材ほど低下が緩い。
- 棄却条件: 反復で評定が下がらない。
- 状態: 未検証

## H8 局所バースト仮説

**主張**: 「速さ」は平均値ではなく**短い区間の密度**として知覚される。平均 ASL や平均 transition-duration が同じでも、局所に連続する変化（バースト）がある方がドパガキ感が高い。

- 予測: 平均値ではなく「3秒窓の変化回数の最大値」「変化間隔の最短値」の方が評定と相関する。
- 根拠の芽: 映画の平均 ASL は 2〜3秒でも、戦闘シーケンスは 0.58秒（[DiVA](https://kth.diva-portal.org/smash/get/diva2:1704346/FULLTEXT01.pdf)）。実在LPの transition 中央値は 300〜500ms で「速い」わけではない（[research/20261116-lp-css-measure.md](../research/20261116-lp-css-measure.md)）。
- 検証方法: 平均を揃えて分散だけ変えた2素材の比較。`tools/measure/probe.js` の `layoutMutations` を1秒窓で記録し、最大値を使う。
- 棄却条件: 平均値と最大値のどちらで見ても評定との差が出ない。
- 状態: 未検証

## H9 制御可能性の独立仮説

**主張**: 刺激の強度と「止められる／減らせる」制御可能性は独立に設計できる。制御を足しても強度の評定は下がらない。

- 予測: 停止ボタンや reduced-motion 対応を足した版と足さない版で、強度の評定がほぼ同じ。
- 検証方法: 同一作品の2版を並べて評定。
- 棄却条件: 制御を足すと強度の評定が明確に下がる（= 強度と制御がトレードオフなら、ゲート設計を「強度を下げる」方向に変える必要がある）。
- 状態: 未検証
- なぜ重要か: この仮説が支持されれば「アクセシビリティ対応＝ドパくなくなる」という誤解を数字で否定でき、`rules/` のゲートを強度を落とさずに運用できる。
