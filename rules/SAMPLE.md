# R-tempo-hold-under-3s — 同じ画面のホールドは3秒を超えない（記入例）

## 規則

主要な画面（ビューポート1つ分）のうち、内容が変化しない時間を **3秒以内** に収める。変化は「次の情報・次の状態・次の動き」のいずれかでよい。

## 実装

- セクション間の最短ホールドを決め、`IntersectionObserver` で入ったらタイマー開始、3秒で次の変化を発火。
- 変化はホールドの 400〜600ms 前から予兆を出す（フェードの開始、カウントダウン、カーソルの変化）。

```js
// 3秒ホールドの最小実装（記入例）
const HOLD_MS = 3000;
new IntersectionObserver(([e]) => {
  if (!e.isIntersecting) return;
  setTimeout(() => advance(), HOLD_MS); // advance は次の状態へ
}, { threshold: 0.6 }).observe(section);
```

## なぜ効くか（仮説）

変化の間隔が短いと「次」への期待が途切れず、内容の精読より先に更新を追う反応になる（H1 テンポ仮説）。
ただし 3秒は上限であって目標ではない。実際の値は [docs/02-taxonomy.md](../../docs/02-taxonomy.md) 付録の参照値と、
対象作品の観察から決める。

## 効く条件

- 情報が「読む」より「流れる」ことが主目的の画面（フィード、LPのヒーロー、演出ページ）
- 同一画面内に複数の情報単位がある

## 効かない・逆効果の条件

- 長文・フォーム・購入確定・エラー表示など、**読み切る必要がある画面**（H5 反発U字の右側に入る）
- 操作の結果を確認させたい場面（押した後の状態遷移を奪うと失敗感が出る）
- 3秒を待たせると「遅い」と感じる場面（待ちが無意味に感じられる）

## 強度の根拠

4（強め）。ホールドの長さは体験全体のテンポ感を支配しやすいが、単独では「ドパガキ」を成立させない
（速度だけでは `intensity` が低いと静かに見える — 観察記入例の反例）。
