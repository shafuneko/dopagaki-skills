# dopagaki-frontend

「ドパガキ」を**再現可能な制作手順**として使うためのスキル。
このファイルは手順書。**規則の実体は [rules/](../../rules/)、根拠は [observations/](../../observations/)、
測定語は [docs/02-taxonomy.md](../../docs/02-taxonomy.md)** にある。ここに規則を書き写さない（二重管理を避ける）。

## 0. 前提

- ドパガキの定義は固定しない。作業定義は [docs/00-what-is-dopagaki.md](../../docs/00-what-is-dopagaki.md) を読む。
- **規則が無い領域は、一般論で埋めない。** 「この軸は規則不足」と明示し、[docs/02-taxonomy.md](../../docs/02-taxonomy.md) の軸で観察メモを残す（[AGENTS.md](../../AGENTS.md) §7）。
- 印象語（うるさい、癖になる）で頼まれたら、まず測定語に翻訳する（[docs/01-method.md](../../docs/01-method.md) の翻訳表）。

## 1. 強度を先に決める（1〜5）

作品全体の「ドパガキ強度」を1つ決め、軸ごとの強度はその内側に収める。

| 強度 | 全体の印象 | 使いどころ |
|---|---|---|
| 1 | ほぼ普通。1か所だけ速い | 企業サイト、読み物、フォーム |
| 2 | 要所でリズムが出る | コーポレートLP、採用ページ |
| 3 | 全編にテンポと密度がある | 商品LP、キャンペーン |
| 4 | 常に何かが動き、止まらない | イベント、エンタメ、若年層向け |
| 5 | 情報の洪水。理解より体感 | アート、演出、SNS的 |

**強度は上げるほど良いのではない。** 5は反発（酔い・読みにくさ・離脱）との勝負になる（H5。反発は [evals/rubric.md](../../evals/rubric.md) で測る）。

## 2. 軸を選ぶ（2〜3個）

10軸のうち、今回の作品で意図的に振る軸を2〜3個だけ選ぶ。全部を同時に上げない。

- `tempo` / `intensity` / `motion` / `reward` / `audio` / `copy` / `flow` / `style` / `restraint` / `backlash`

**`restraint`（抑制）は必ず1つ入れる。** 刺激は対比で効く（H6）。静区間ゼロの作品は強度を上げても単調になる。

## 3. 規則を引く

- [rules/](../../rules/) を開き、選んだ軸の `domain` で絞る。`status: adopted` かつ `strength` が目標強度に近いものを優先。
- 規則を適用する前に「効かない・逆効果の条件」を読み、今回の作品がそこに当たらないか確認する。
- 規則が足りない → 足りないと明示して制作を続け、終わったら観察メモを残す（§6）。

## 4. 実装

- 数値は [docs/02-taxonomy.md](../../docs/02-taxonomy.md) の付録（外部参照値）から出発し、**作品内で一貫させる**（画面ごとに transition がバラバラだと意図が消える）。
- 制御可能性は強度と**独立**に必ず確保する（下のゲート）。ここを落とすと作品として不可。
- 反発チェック: 移動量・点滅・コントラスト・止められるか（[evals/rubric.md](../../evals/rubric.md)）。

### 必須ゲート（満たさない作品は不可）

- 5秒を超える移動・点滅・自動更新に**停止/一時停止**の手段（WCAG 2.2.2）
- 1秒に3回を超える閃光なし（WCAG 2.3.1）
- 音付き自動再生を勝手に始めない、または**ミュートでも成立**する（WCAG 1.4.2 / Chrome autoplay）
- `prefers-reduced-motion: reduce` で動きを減らせる（WCAG 2.3.3 相当。前庭障害対策）
- 本文のコントラスト比を確保（動きの中でも読める文字は読める状態に）

## 5. 自己評価

[evals/rubric.md](../../evals/rubric.md) で採点する。点数は主観を含むので、1回の採点で断言しない。
強度目標と実測スコアがずれていたら、規則の適用が過剰か不足。

## 6. 記録（次に使う人のため）

- 適用した規則ID、変えた数値、判断した理由を残す（コミットメッセージか制作メモ）
- 新しい傾向に気づいたら [observations/](../../observations/) に1ファイル、パターン化できそうなら [patterns/](../../patterns/) へ提案
- この骨組み自体を変えたら 4点セット: 索引更新 / ADR 1枚 / [chat.md](../../chat.md) 引き継ぎ / 相手の未コミットを壊さない

## 7. 入力の前提・出力・完了条件

**前提（足りなければ先に聞く）**
- 何を作るか（新規 / 既存の改修）、対象（LP・アプリUI・動画のテロップ・ゲーム画面など）
- 目標強度（1〜5。言われなければ3を仮置きして「仮」と伝える）
- 制約（納品先のガイドライン、対応ブラウザ、音の可否、締切）

**出力**
- 実装（コード）と、**どの規則をどの数値で適用したか**の短い一覧
- ゲートの充足状況（§4 の5項目、それぞれ満たした／満たしていない）
- 自己評価（§5）と、残った「規則不足」の軸

**完了条件**
- ゲート5項目がすべて満たされている
- 目標強度とスコアのずれが説明できている（ずれたまま終わらせない）
- 適用した規則IDと変えた数値が記録されている（§6）

## 8. 参照の読み順（深追いしない）

1. このファイル（手順）
2. [rules/README.md](../../rules/README.md) → 該当 `domain` の規則だけ開く
3. 数値が必要なら [docs/02-taxonomy.md](../../docs/02-taxonomy.md) の付録
4. 根拠を疑うときだけ [observations/](../../observations/) と [patterns/](../../patterns/)
5. 背景（語源・批判・倫理）は [docs/00-what-is-dopagaki.md](../../docs/00-what-is-dopagaki.md)

**references/ の中は、このスキルの外に置かれた資料への入口**として扱う（[references/README.md](references/README.md)）。規則の本文をここへ複製しない。

## うまくいかないとき

- **規則が1本も当たらない** → 規則不足。一般論で埋めず、[docs/02-taxonomy.md](../../docs/02-taxonomy.md) の軸で観察メモを残して終わる（[AGENTS.md](../../AGENTS.md) §7）。
- **ゲートを満たすとドパくならないと言われた** → 制御可能性と強度は別軸（H9）。止められるまま強度を上げる方法を探す。ゲートを外す選択はしない。
- **実装したが「安っぽい」** → 速さではなく `intensity`（色数・密度）と `style`（質感・一貫性）を見る（[research/20261116-visual-density.md](../../research/20261116-visual-density.md)）。
- **点数が目標と大きくずれる** → 採点のばらつきか、規則の適用過剰か不足。1人で決めず、[evals/README.md](../../evals/README.md) の手順で2人目の採点を取る。

## よくある失敗

| 失敗 | 兆候 | 対処 |
|---|---|---|
| 全軸を強度5にする | 酔う・読めない・全部同じに見える | 軸を2〜3個に絞り、`restraint` を入れる |
| 速さだけ上げる | 「速いが安っぽい」 | `intensity`（色数・密度）と `style`（質感）を同時に見る |
| 規則の「効く条件」を読まない | フォームや決済画面でテンポを上げて失敗する | 適用前に逆効果条件を確認 |
| 静区間ゼロ | 強度を上げても単調 | `restraint` を意図的に配置（H6） |
| 制御可能性を後回し | 監査で不可 | §4 のゲートを実装初日に確保する |
