# dopagaki-direction — ドパガキ演出

「ドパガキ」を**演出の文法**として使うためのスキル。

ここで作るのは「ドパガキっぽい作品」ではなく、**ドパガキ演出**そのもの。
参照する型は、パチンコ・スロットの液晶演出にある
**「期待を段階的に吊り上げ、虹色と閃光で当たりを祝う」**構造。

このファイルは手順書。**規則の実体は [rules/](../../rules/)、根拠は [observations/](../../observations/)、
測定語は [docs/02-taxonomy.md](../../docs/02-taxonomy.md)** にある。ここに規則を書き写さない。

**`status: draft` の規則は「合意前の試案」で、確定指針として適用しない。**
採用するときは根拠（観察・反例）を確認し、作品ごとに採否を決めて、その判断を記録に残す。
`adopted` は2人のレビューを経たものだけ。現時点（2026-11-16）で `adopted` は0本。

- パチンコ・スロットの用語と段階 → [`references/pachinko-slot-grammar.md`](references/pachinko-slot-grammar.md)
- 虹色・発光・集中線・グリッチのレシピ → [`references/spectacle-recipes.md`](references/spectacle-recipes.md)
- 段階の設計テンプレとタイムライン → [`references/escalation-ladder.md`](references/escalation-ladder.md)

## 0. 前提

- ドパガキの定義は固定しない。作業定義は [docs/00-what-is-dopagaki.md](../../docs/00-what-is-dopagaki.md)。
- **規則が無い領域は、一般論で埋めない。** 「この段階は規則不足」と明示して進め、観察メモを残す（[AGENTS.md](../../AGENTS.md) §7）。
- 演出と賭博性は別問題。**射幸心を煽る構造（当落・景品・換金）を持ち込む場合は、景品表示法・各プラットフォーム規約の確認が別途必要**（このスキルの範囲外。ここで作るのは「見た目と時間の設計」）。
- 人身の安全（閃光・前庭・音）は演出の一部として扱う。**「派手にできないから弱くする」のではなく、「派手なまま止められる・減らせる」を作る**（H9 制御可能性の独立）。

## 1. 演出を「段階」で設計する

強度1〜5のような一次元の値ではなく、**段階（ステージ）のラダー**で作る。
パチンコ・スロットの液晶が「通常 → 予告 → リーチ → 発展 → 大当り → 確変」と進むのと同じ形。

| 段階 | 名前 | 画面で起きること | 時間の目安 |
|---|---|---|---|
| L0 | 通常 | 静止に近い。基準点。ここがあるから次が効く | 全体の50〜70% |
| L1 | 予兆（先読み） | 小さな違和感。色が1つ変わる、音が1つ増える、動きが1回入る | 1〜2秒 |
| L2 | リーチ | 主要素が揃いかける。テンポが上がる。期待が言葉になる | 2〜4秒 |
| L3 | 発展 | 画面構成が変わる。別レイヤが乗る。ここで一度**止める** | 1〜3秒 |
| L4 | 大当り | 虹色・閃光・集中線・文字・音が同時に開く | 1.5〜4秒 |
| L5 | 確変 / MAX | 状態として続く。倍率・色・BGM が常時高い。**ここに停止手段を必ず置く** | 10秒〜 |

- **段階は3つ以上**。L0 と L4 だけの2段は「静か→爆発」で、期待の過程がない。
- 段階の差は**量ではなく種類**で作る。L2 で速くしたなら L3 は「遅くして止める」でもよい。
- 各段で変える項目は **色 / 速度 / レイヤ数 / 音 / 文字 / 抽選** の6つ。1段につき2つ以上を同時に変えると「段が上がった」と知覚されやすい（1つだけだと気づかれない）。

## 2. 期待感を設計する

演出の強さは「光の量」ではなく**予告と当落の設計**で決まる。

- **何を予告するか**を1文で言えるようにする（例:「このあと倍率が上がる」「このリールが揃う」）。
- **外れても楽しい**外れ方を用意する。外れが「損」だけだと、次の期待が生まれない。
- **先読み**（本番の前に小さいシグナルを出す）と**保留**（次の演出を溜めておく）を、UI の状態として持つ。
- **当たりの瞬間に情報を増やさない**。当たりは「祝う」段階。新しい説明を読ませない。

## 3. 技法を選ぶ（6カテゴリ）

| カテゴリ | 何を使うか | レシピ |
|---|---|---|
| 虹色 | 色相環の回転、多色グラデ、`hue-rotate` | [`spectacle-recipes.md`](references/spectacle-recipes.md) §1 |
| 発光 | 多層 shadow、`mix-blend-mode`、白フラッシュ、`brightness`/`saturate` の脈動 | 同 §2 |
| 光線 | `repeating-conic-gradient` の放射、SVG の線、Canvas パーティクル | 同 §3 |
| 揺れ・崩れ | 画面振動、グリッチ、clip-path 分割、RGB ずらし | 同 §4 |
| 文字 | 極太縁取り、1文字ずつ、傾き、バウンド | 同 §5 |
| 記号（射幸） | リール、図柄、抽選、倍率の階段、保留 | 同 §6 |

**派手さの作り方の順序**（ここを逆にすると安っぽくなる）:

1. 背景を暗くする（黒に近い。発光は暗さの中でのみ強く見える）
2. 高彩度の色を**少数**に絞る（3〜4色。虹色は「回す」ことで多色に見せる）
3. 光を足す（shadow / blend）
4. 動きを足す（回転・脈動・振動）
5. レイヤを重ねる（背景 → 図柄 → 光 → 文字 → 前景の粉）

## 4. 実装

- **タイムラインを先に書く**。どの段階が何秒で、何が変わるかを表にしてからコードを書く（[`escalation-ladder.md`](references/escalation-ladder.md) のテンプレを使う）。
- 数値は [docs/02-taxonomy.md](../../docs/02-taxonomy.md) の付録から出発し、**作品内で一貫させる**。段階ごとに duration を変えるのは意図的な場合だけ。
- 色は CSS 変数で持つ（`--hue` を回す、`--glow` を上げる）。段階は `data-stage="L2"` のような属性で切り替え、JS は段階の遷移だけを担当する。
- 音は「段階の変化」に同期させる。音を足すのは L3 以降、L4 で一気に重ねる。
- 常時ループ（L5）は**必ず止められる**ようにする。ループの `animation` は `animation-play-state` で止まる形にする。

### 必須ゲート（満たさない作品は不可）

- 1秒に3回を超える閃光・点滅を入れない（WCAG 2.3.1。面積の条件もある。虹色の**色相回転は輝度を動かさない**ので閃光には当たりにくいが、白フラッシュを重ねると当たる）
- 5秒を超える移動・点滅・自動更新に**停止/一時停止**の手段（WCAG 2.2.2）。L5 を置くなら必須
- 音は**勝手に鳴らさない**、またはミュートでも成立する（WCAG 1.4.2 / Chrome autoplay）
- `prefers-reduced-motion: reduce` で動きを減らせる（WCAG 2.3.3 相当）。**演出を消すのではなく、回転と振動を止めて色と光は残す**
- 本文のコントラスト比を確保（動きの中でも読める文字は読める状態に）
- 前庭刺激（大きな移動・回転・ズーム）は reduced-motion で止める

## 5. 自己評価

[evals/rubric.md](../../evals/rubric.md) で採点する。演出特化の場合、`A 濃度` `B 速度` `C 予測不能性` `D 様式の過剰さ` に加えて、
**E 段階の設計**（段階数・各段の変化の種類・止める位置）と **R 反発**（酔い・読みにくさ・うるささ）を見る。
点数が高い＝良い演出ではない（H10）。目標は「狙った段階に到達していること」。

## 7. 入力の前提・出力・完了条件

**前提（足りなければ先に聞く）**
- 何を作るか（新規 / 改修）、対象（LP・UI・ゲーム画面・動画テロップなど）
- 到達させたい段階（L1〜L5。言われなければ L3 を仮置きして「仮」と伝える）
- 何を予告する演出か（当落・抽選・倍率・解放など）
- 制約（納品先ガイドライン、対応ブラウザ、音の可否、締切）

**出力**
- 実装（コード）＋**段階表**（L0〜L5 の時間・変化・技法）
- 適用した規則IDと数値の一覧
- ゲートの充足状況（§4 の6項目、それぞれ満たした／満たしていない）

**完了条件**
- 段階が3つ以上あり、各段で変化の種類が2つ以上ある
- L4（大当り）と L5（常時）に停止手段がある
- 閃光の回数・面積が基準内
- reduced-motion で「動きを止めても演出の意図が残る」

**うまくいかないとき**
- 派手に見えない → 色数を増やすのではなく、**背景を暗くして光を足す**
- チープに見える → 段階を飛ばしている（L1・L2 を入れる）、または全部の段で同じ技法を使っている
- 酔う・うるさいと言われた → 移動と点滅を減らし、代わりに**色相と光**で強度を保つ
- 止められないと言われた → ループを `animation-play-state` で止め、状態を L0 に戻す導線を作る
